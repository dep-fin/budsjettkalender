# EV04 – varseltyper og vesentlige direkte endringer

Lokal kandidat for [#114](https://github.com/depmartin/Budsjettkalender/issues/114),
med [#110](https://github.com/depmartin/Budsjettkalender/issues/110) som kravkontekst.
Bygget fra merget EV03 `93b1aea3f0953535e3144d22b36991e88ead7852` på
`codex/114-varseltyper` i isolert checkout. Review, sikkerhetsaudit, publisering og
kandidat-CI håndteres samlet etter byggingen. Denne filen er ingen merge- eller
produksjonsaksept.

## Levert atferd

- To uavhengige varselvalg ved påmelding og i egne innstillinger. Minst én kreves;
  valg bekreftes uttrykkelig. Eierskap kommer fra serverens autentiserte identitet.
  En gammel abonnementsversjon avvises uten å overskrive en nyere innstilling eller avmelding.
- Direkte administratorredigering registrerer semantisk vesentlige endringer i
  dato, klokkeslett, presisjon, måned, kvalifikator, budsjettår og kategori. En annen
  referansedag i samme tentative måned eller meningsløst klokkeslett/kvalifikator
  gir ingen hendelse. Vanlig tekstkorrektur varsles ikke automatisk.
- Administrator kan markere annen faktisk innholdsendring med en forklaring på
  1–300 tegn. Uendret innhold, tom/lang forklaring og kontrolltegn avvises. Valget
  kan ikke slå av automatisk vesentlighet. Frist, synlighet, før-/ettermetadata,
  forklaring og publiseringssekvens følger samme lagringstransaksjon.
- Hendelser grupperes per frist. Relevant ny publisering vises én gang med siste
  tilstand; endringer alene viser første relevante førverdi og siste tilstand.
  Tekst- og HTML-meldinger viser dag/tid eller tentativ periode, budsjettår,
  kategori, hendelsestype og vanlig kalenderlenke med innloggingskrav. Endret tittel,
  løp og notat viser også feltets første relevante førverdi og gjeldende etterverdi.
  Tilføyd eller tømt løp/notat viser «(ikke angitt)» på den tomme siden. Uendrede
  tekstfelt gjentas ikke. Tekstverdier og forklaringer HTML-kodes. Tentative perioder
  får ingen oppdiktet dagsdato.
- Hver type har egen eksklusiv nedre sekvensgrense. Utvidelse flytter bare den
  nye typens grense; den andre typens ventende varsler beholdes. Av/på gir ikke
  etterslep fra avslått periode, også når klokken står stille eller går bakover.
  Aktive EV02-abonnementer uten aktiveringsrad beholder den andre typens implisitte
  grense 0 ved første utvidelse. Innskrenkning og avmelding revalideres før sending.
- Dagens godkjente frist og synlighet samt fersk mottakertilgang begrenser også
  førverdier og forklaringer. Eksisterende kontroll før transport, dagsvern,
  omstartshåndtering og vern mot gjentakelse etter uavklart overlevering består.

## Lagring og migrasjon

EF 10.0.9 genererte `20261028165341_VarseltyperOgEndringer`, Designer og snapshot.
Migrasjonen utvider den eksisterende hendelsestabellen uten å bytte ID-er, med Type
Ny for gamle rader og nullable før-/ettermetadata og forklaring. Den filtrerte unike
FristId-indeksen bevarer førstegangspubliseringsvernet. Aktiveringsraden får en
egen endringsgrense; eksisterende abonnementer og planer tilbakefylles ikke.

Normal SQLite-demooppstart oppgraderer EV02 og EV03 atomisk og idempotent. Prøvene
bevarer frister, kilder, forslag, synlighet, feed, interndata, abonnementer,
aktiveringsgrenser, hendelses-ID-er, planer og hendelseskoblinger. En ventende
EV03-plan kan fullføres etter oppgraderingen. Historiske migrasjonsmål beholder
sine reelle skjemaassertions; bare siste mål sammenliknes med dagens snapshot.
Ingen ventende modellendringer finnes. SQL Server har de samme delte kontraktene
og en særskilt oppgradering fra autentisk levert EV03-migrasjon.

## Gjenstående porter

Samlet Standards-/Spec-review, separat sikkerhetsaudit og etterkontroll før
publisering er dokumentert for `c8ca65d` / identisk publisert tre i
[oppgaven](https://github.com/depmartin/Budsjettkalender/issues/114#issuecomment-6477612285).
Denne avgrensede CI-runden følger ticket-orchestrators retteløkke uten nytt review
eller sikkerhetsaudit. Ny faktisk kandidat-CI, inkludert ekte SQL Server og
Chromium, må bestå etter rettingen før merge. Ingen lokal SQL Server-tilkobling er
konfigurert; oppdagelse og SQL Server-målmodell beviser ikke kjøring.
Edge/SQLite og kontrollerte adaptere beviser ikke Entra-/gjestebrukertilgang,
Azure SQL eller faktisk M365-levering. Produksjonsadaptere er fortsatt stengt.
Kø/generering, import/sletting, års-/kategorifiltre, adressebytte, avmelding fra
e-post og administrasjon/drift er senere EV-tickets. Ingen produksjonsutrulling
eller eksterne tilgangsendringer er utført.
