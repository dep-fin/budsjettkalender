# Atelier UX05 – Budsjettår med Tidslinje og Fristliste

Lokal kandidat for [#80](https://github.com/depmartin/Budsjettkalender/issues/80),
27. oktober 2026. Base: `19d7949d1950d3bc8319430b3d62eacaefd54783`, den mergede
UX04-leveransen i [PR #99](https://github.com/depmartin/Budsjettkalender/pull/99).
Hele [#75](https://github.com/depmartin/Budsjettkalender/issues/75), #80 og de aktuelle
kommentarene er lest. Den grønne [samlede Atelier-referansen](https://github.com/depmartin/Budsjettkalender/tree/e517ed91a066872c3947e8c463704655b6cd3313/docs/prototypes/atelier-samlet-2026-10-27)
er det visuelle utgangspunktet. Prototypen er referanse, ikke produksjonskode eller testbevis.

## Implementert atferd

`/budsjettaar` starter med Tidslinje og ett autorisert budsjettår. Tidslinje og
Fristliste leser samme komplette utvalg fra IFristlesing med valgt Budsjettaar og
InkluderHistorikk=true, uten kategori- eller datogrense. Dermed inngår også historisk
Regnskap. Kalenderens søk, årsvalg og kategorier avgrenser ikke budsjettårsutvalget.
Startåret er det tilgjengelige året nærmest dagens Oslo-år, med laveste år ved lik avstand.

Tidslinjen viser oktober t−2–april t+1, kalenderår, relativt år og de fem avtalte
standardfasene. Frister før og etter vinduet har sammenhengende, navngitte felt.
Tette måneder åpner grupper med alle fristene, i stabil dato-/tid-/tittel-/ID-rekkefølge.
Tentative måneder har egne bånd og beholder måned og primo/medio/ultimo uten en fast dag.
I dag har tekstetikett og faktisk Oslo-dato. Når dagen er utenfor aksen, forklares dette.
Datoregnskapet bruker long og klipper bare presentasjonen til DateOnly-området.
Fasene er lesende standardverdier; lagring og editor kommer i #83.

Begge presentasjoner åpner eksisterende Fristdialog med full tittel, dato/tid,
kategori, budsjettår, notat, trygg kilde og gjeldende rollehandlinger. Kilderundskriv
står over Om fristen. Forsinket modulimport og nettleserens native fokusretur består.
Vis i kalenderen går til fristens måned, bevarer eksisterende årsvalg/søk/kategorier
og legger til målets budsjettår når det mangler. En synlig melding forklarer bevarte
filtre som skjuler målet, med Endre kalenderutvalg. Tentative overganger åpner måneden
og oppgir at dato ikke er fastsatt, uten å presentere referansedagen som en fast fristdag.

Fristliste har det eksplisitte valget Flere år og historikk. Dette bruker tidligere
Filterpanel/Visningstilstand, med flere årsvalg, egne kategorier, historikk og
null/tom=alle-semantikken. `/aarshjul` åpner dette valget direkte. Vis hele budsjettåret
går tilbake til den komplette enkeltårslisten. Det finnes fortsatt én Budsjettår-fane.
Valg i den eldre listen lever i samme Blazor-krets og nullstilles ved full lasting.
Datamodell, migrasjoner, publisering, synlighet og API-kontrakter er uendret.

## Faktiske prøver

Seks nye Playwright-scenarioer i BudsjettaarTester kjører mot ekte Kestrel, Blazor,
Edge og disponible SQLite-databaser. Frister og forslag opprettes gjennom UI.
Syntetiske dokumentkoblinger og kontrollert utilgjengelig/tom lesetabell er oppsett
i scenarioets egen database. Retur og atferd kontrolleres gjennom nettleser og lese-API,
som bruker IFristlesing. Ingen CSS eller privat komponenttilstand brukes som testfasit.

| Krav | Observerbart bevis |
| --- | --- |
| Komplett enkeltår | Budsjettår 2026 har samme ID-sett i API, Tidslinje og Fristliste, inklusive august 2024, historisk Regnskap januar 2025, november 2026 og august 2027; dato, kategori og notat leses i begge visningers detaljer |
| Årsbytte og vindu | 2028 viser sitt eget innhold, retur til 2026 gjenoppretter hele settet; før-/etterfelt inneholder fristene utenfor standardvinduet; fem standardfaser vises uten skrivekontroller |
| Tette frister | Ni faste frister samme dag, inklusive heldag, 00:05, seks samtidige 13:45 og 23:55, er individuelt tilgjengelige; samtidige A–F har stabil tittelrekkefølge |
| Tentativ presisjon | November med ingen kvalifikator, primo, medio og ultimo kan åpnes fra begge presentasjoner; dialogene viser måned/kvalifikator og ingen falsk 15.-dato eller klokkeslett |
| Kilde og roller | Leser, FA-bidragsyter, FIN-FAG-bidragsyter og administrator får samme tillatte HTTPS-kilde og fullstendige detaljer, med eksisterende rel/referrer-vern og rollehandlinger; kildefri frist har ingen tom kildeseksjon |
| Serververn | Skjult POL-tittel/ID/år, upublisert forslag/år og rå dokumentmetadata finnes ikke i vanlig lesers DOM; begge presentasjoners ID-sett samsvarer med personens lese-API |
| Kalenderovergang | 2026 + 2028 og søk/kategori beholdes ved fast frist; mål i 2027 utvider unionen med 2027; skjulende kategori og søk forklares uten nullstilling; Endre kalenderutvalg virker; tentativ desember åpner måneden uten å velge lagret 15.-dag som mål; direkte overgang før første kalenderbesøk initialiserer de tilgjengelige årsvalgene |
| Eldre liste | Direkte `/aarshjul`, flerårsvalg 2026 + 2028, Regnskap og historikk virker; kategori/historikk lever videre i samme krets, normal enkeltårsvisning inkluderer likevel historisk Regnskap, og full lasting gjenoppretter gamle standardvalg |
| Mobil og tastatur | På 390 × 844 åpnes alle de nye tette og tentative fristene med Space, detaljoverskrift får fokus, Escape lukker og returnerer fokus; sidebredden overstiger ikke visningsbredden |
| Feil og tomt | Kontrollert utilgjengelig lesetabell gir trygg norsk feil med Prøv igjen i begge presentasjoner; gjenoppretting virker, og helt tomt autorisert utvalg gir lesbar tomtilstand også på mobil |

Seks nye HTTP-tilfeller i BudsjettaarHttpTester bruker faktisk prerendering og
IFristlesing mot SQLite. År 1, 9999, int.MinValue og int.MaxValue beholder sine
frist-ID-er og godkjente Regnskap-data ved datogrensene uten overløp eller ny
skrivevalidering. Injisert TimeProvider ved 23:30 UTC i oktober og 22:30 UTC i juni
gir henholdsvis 27. oktober og 1. juli i synlig I dag-tekst og datetime-attributtet.
Dette kontrollerer både vinter-/sommertid gjennom den offentlige HTTP-flaten.

Alle 41 tidligere nettleserscenarioer beholdes. Tester for tidligere listehistorikk
går nå via det eksplisitte kompatibilitetsvalget før samme atferd prøves. Den
forsinkede importprøven kontrollerer fortsatt fravær av en åpen foreldreløs dialog;
den felles, lukkede dialogkomponenten kan nå finnes på Budsjettår-siden.
Rolleprøvens aktive Fristliste velges gjennom samme kompatibilitetsinngang og
kontrolleres nå med knappens aria-pressed, som erstatter den tidligere lenkens aria-current.

## Rød → grønn og sluttkontroll

`TestResults/80-test-red.trx` er den første prøven: den feilet i faktisk UI fordi
Velg budsjettår manglet. Utvidede prøver fant dessuten at historikkavhuking ble synlig
mens fristlisten beholdt gamle data. Lastingen måtte varsle ferdig render også ved
hendelser fra kompatibilitetsfilteret. Denne atferden beholdes som regresjonstest.
Testenes tilgjengelige årsvelger og entydige dialogoverskrift ble deretter presisert;
fravær av kilde kontrolleres først etter at dialogens synlige fokus bekrefter åpningen.

`TestResults/80-test-green3.trx` har alle seks nye nettleserscenarioer grønne.
Den første fulle kjøringen fant også en ny sideoverskrift med samme navn som H1.
Sidepanelets tidligere Velg utvalg er gjenopprettet, slik at de eksisterende
navigasjons-/fokusprøvene beholdes uten mindre presise forventninger.

Sluttkjøringen bruker SDK 10.0.402, låst restore og Release-bygg for ordinær løsning,
BrowserTests og SqlServerTests. Sårbarhetskontroll er aktiv. En tidlig sandbox-restore
ga NU1900 på grunn av nettverkstilgang; ny, tvungen restore med nettverkstilgang
fjernet den, og sluttrestores har ingen NU1900. Den eksisterende CS0649-advarselen
for Runde._feil er uendret.

Etter siste kilde- og testendring passerer **639 ordinære tester og 47 reelle
Edge/Kestrel-scenarioer, 0 feil og 0 hopp**. Alle 633 ordinære og 41 nettleserprøver
fra forgjengeren er med i dette resultatet.

Sluttresultater etter P3-rettingen: `TestResults/80-review-fix-ordinary.trx` og
`TestResults/80-review-fix-browser.trx`; byggeloggen er
`TestResults/80-review-fix-build.log`. Lokale app-/databasefiler ligger i
`TestResults/80-review-fix-browser/`. CI og utviklingsveiledningen krever nøyaktig
47 beståtte nettleserscenarioer uten hopp.

## Samlet gjennomgang og avgrenset retting

Full Standards-/Spec-gjennomgang er utført mot base
`19d7949d1950d3bc8319430b3d62eacaefd54783` ved kandidat
`354dcdc2399ce79e32b380c59b5c11b564ed3a24`. Standards fant ett P3-funn om duplisert
søkematching i Kalender. Spec, inklusive visuell kontroll, hadde ingen funn.
Separat sikkerhetsaudit ved samme kandidat hadde ingen funn; de 110 målrettede
HTTP-/sikkerhetstestene passerer uten feil eller hopp i
`TestResults/80-security-review.trx`.

Byggerens grønne baseline ved denne kandidaten er bevart som
`TestResults/80-test-final3-{ordinary,browser}.trx` og
`TestResults/80-test-final3-build.log`. De fulle gjennomgangene er ikke gjentatt
etter den avgrensede rettingen; den målrettede etterkontrollen håndteres separat.

P3-funnet er rettet ved å samle tittel-/notatpredikatet i én privat, lokal
`TrefferSoek`-metode. Både faktisk kalenderfiltrering og kalenderovergangens
forklaring bruker denne. Eksisterende trimming, tomt-/blankt søk, nullhåndtering
av notat og `StringComparison.OrdinalIgnoreCase` er bevart. Tilstand, UI,
serverfiltrering og øvrige kontrakter er uendret.

De eksisterende offentlige nettleserscenarioene for søk i tittel/notat og
kalenderovergang passerer etter rettingen: **2 av 2, 0 feil og 0 hopp** i
`TestResults/80-review-fix-targeted-browser.trx`. Søkeprøven dekker trimming,
norske store/små bokstaver, tittel-/notattreff, nulltreff og nullstilling.
Overgangsprøven dekker bevart søk/kategori/årsunion, synlig notattreff og forklaring
når søket skjuler målet. Ingen test av en privat implementasjonsdetalj er lagt til;
dette er en refaktorering fra gjennomgangen uten endret atferd eller ny rød fase.
Deretter er låst restore og Release-bygg av ordinær løsning, BrowserTests og
SqlServerTests kjørt på nytt med SDK 10.0.402. Etter siste kodeendring passerer
hele den ordinære suiten med 639 tester og hele Edge/Kestrel-suiten med 47
scenarioer, uten feil eller hopp, i sluttresultatene ovenfor. Sårbarhetskontroll
er aktiv, ingen NU1900 forekommer, og bare den eksisterende CS0649-advarselen består.

## Visuell kontroll

25 faktiske bilder fra separat Kestrel/SQLite/Edge er tatt og inspisert med
view_image i `TestResults/80-visual/`. Leser og administrator har hvert sett av
`timeline-desktop.png`, `list-desktop.png`, `details-desktop.png`,
`compatibility-desktop.png` og tilsvarende mobilbilder, med prefiks `reader-`
eller `admin-`. Leseren har i tillegg `reader-{outside,dense,tentative}-{desktop,mobile}.png`
og `reader-{calendar-transfer,error,empty}-mobile.png`.

Desktop er 1440 × 1000, mobil 390 × 844. `capture-result.json` har tom feilliste,
og alle 25 tilfeller har sidebredde lik visningsbredden. Den grønne Atelier-paletten,
Segoe UI, fire ruter i merket, header/sidebar og luft er bevart. Tidslinjen viser
kalenderår 2024–2027, relative år, hvit graf, kort/stilker, fem svakt fargede faser
og rød Oslo-markør bak kortene. Mobilgrafen ruller internt; liste og detaljer
forblir lesbare i visningsbredden. Tette og tentative grupper, før-/etterfelt,
rolletilpassede kilder/handlinger og kompatibilitetsutvalget er kontrollert.

`TestResults/80-visual/capture.cjs`, bilder, database og applogg er ignorert lokal
evidens. Ingen abonnementsside eller token-URL er tatt bilde av eller publisert.

## Gjentaking og bevisgrenser

Bruk SDK 10.0.402 i global.json og [utviklingsoppsettet](../development.md).

```powershell
dotnet restore backend/Aarshjul.slnx --locked-mode
dotnet restore backend/Aarshjul.BrowserTests/Aarshjul.BrowserTests.csproj --locked-mode
dotnet restore backend/Aarshjul.SqlServerTests/Aarshjul.SqlServerTests.csproj --locked-mode
dotnet build backend/Aarshjul.slnx -c Release --no-restore -m:1 -nr:false
dotnet build backend/Aarshjul.BrowserTests -c Release --no-restore -m:1 -nr:false
dotnet build backend/Aarshjul.SqlServerTests -c Release --no-restore -m:1 -nr:false
dotnet test backend/Aarshjul.Tests -c Release --no-build --filter FullyQualifiedName~BudsjettaarHttpTester
dotnet test backend/Aarshjul.BrowserTests -c Release --no-build --filter FullyQualifiedName~BudsjettaarTester
dotnet test backend/Aarshjul.BrowserTests -c Release --no-build --filter 'FullyQualifiedName~Kategori_soek_periode|FullyQualifiedName~Kalenderovergang_' --logger 'trx;LogFileName=80-review-fix-targeted-browser.trx' --results-directory TestResults
dotnet test backend/Aarshjul.slnx -c Release --no-build --logger 'trx;LogFileName=80-review-fix-ordinary.trx' --results-directory TestResults
dotnet test backend/Aarshjul.BrowserTests -c Release --no-build --logger 'trx;LogFileName=80-review-fix-browser.trx' --results-directory TestResults
```

Lokalt brukes AARSHJUL_DOTNET med full SDK-bane og AARSHJUL_BROWSER_CHANNEL=msedge.
Dette er SQLite/Edge-bevis. SQL Server-prosjektet bygges, mens ekte SQL Server og
Chromium fortsatt er obligatoriske CI-porter. Full Standards-/Spec-review og separat
sikkerhetsaudit er dokumentert ved kandidaten ovenfor; målrettet etterkontroll av
P3-rettingen og kandidatens CI gjenstår ved denne overleveringen. Demo dokumenterer
ikke Entra, Azure SQL eller M365 og er ikke pilotakseptanse med brukere. #81 og senere
er utenfor denne kandidaten. Ingen commit, PR, merge eller deploy er utført av byggeren.
