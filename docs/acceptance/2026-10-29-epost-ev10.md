## Observerbar atferd

Administrator-innstillinger har lenken «Åpne e-postabonnenter» til
`/admin/innstillinger/epostvarsling`. Flaten viser bare registrerte og påbegynte
abonnementer, inkludert avmeldte. Den starter i abonnementstabellen og bruker
eventuelt appkjent navn; manglende navn vises som stabil brukeridentitet.
Lesing oppretter eller synkroniserer ingen kontoer.
De seks eksisterende administrasjonsområdene er beholdt. Kalenderfeed på
`/admin/abonnement` er fortsatt en egen flate.

Oversikten viser identitet/navn, adresse, bekreftelsesstatus, abonnementsstatus,
faktiske varseltyper, lagrede budsjettår/kategorier, opprettelse, siste endring,
adressebekreftelse og siste administratorstans med aktør/tid. Null-utvalg vises
som Alle, inkludert fremtidige budsjettår. Kalenderens visningsfiltre påvirker
ikke denne kontrakten. Adressebekreftelse følger Aktivert, som beholdes ved
avmelding og tømmes ved krav om ny adressebekreftelse.

Stans viser abonnent, adresse og status før uttrykkelig bekreftelse.
Avbryt endrer ingenting. Stans krever sist leste versjon. Samtidig adresse-,
filter-, bekreftelses- eller livssyklusendring gir konflikt; flaten leser på nytt
og krever ny bekreftelse. Brukeren kan senere melde seg på og bekrefte igjen.
Rolle, Entra-kilde og gruppemedlemskap beholdes.

## Servergrense og revisjonsspor

HTTP og side bruker `Autorisasjon.ErAdministrator`. Kretskommandoen kontrollerer
autentisert principal og `IAuthorizationService` ved hver lesing/stans, også etter
nedgradering. FA alene avvises. Aktøridentiteten bindes til objectidentifier,
oid, NameIdentifier eller sub i denne prioriteten. POST kan velge abonnent,
versjon og bekreftelse, og kan ikke velge aktør eller endre andre abonnementsfelt.

`/api/admin/epostabonnenter` er lesing. JSON-POST til `/stans` krever
`brukerId`, `versjon` og `bekreftet`. Manglende bekreftelse eller mål gir 400,
gammel versjon 409, feil innholdstype 415 og lagringsfeil trygg JSON/503.
Alle svar, inkludert avvisning og feil, har no-store. Inngangene har ingen CORS.

Stans tar EV09s korte Epostrekkefolge-lås og deretter abonnementsradens lås.
Gjeldende rad leses etter låsen. Avmeldt/Endret og tømt adressebekreftelsesrett
lagres atomisk med audit. Tapende forsøk og gjentatt stans av allerede avmeldt
abonnement gir ingen falsk audit. En mislykket auditinnsetting ruller også
abonnementsendringen tilbake. Samme tjeneste kan brukes på nytt etter feil.

Epostadministratorstanser inneholder bare databasegenerert ID, abonnentidentitet,
aktøridentitet, UTC-tid og handling. Ingen adresse, fristinnhold, melding, token
eller hash inngår. Siste hendelse velges etter varig innsettingsrekkefølge, også
ved korrigert UTC-klokke. Historikken beholdes gjennom gjenpåmelding.

EV09s synkrone `StartOverlevering` beholder låsen gjennom transportmottaket.
Administratorstans før mottaket hindrer videre overlevering; etter mottaket er
meldingen allerede overlevert. Senere kvittering ventes uten lås.
UnderSending/Uavklart, avmeldingsrett og hendelseskoblinger beholdes uten blind
retry. Ny full påmelding/bekreftelse setter nye grenser uten inaktivt etterslep.

## Lagring og oppgradering

`20261029170000_Epostadministratorstans` er additiv og har Designer og snapshot.
Historiske Up/Down og begge `20261029092000`-ID-er beholdes. Modellprøver
sammenlikner faktisk Up/Down med autentiske målmodeller og krever
`HasPendingModelChanges=false` for SQL Server.

Demooppgradering fra EV09 oppretter en tom audittabell i samme transaksjon som
indeksen. SQLite får INTEGER PRIMARY KEY med autoincrement; SQL Server får
identity. Feil under indeksoppretting ruller hele overgangen tilbake og tillater
nytt forsøk. Tidlig retur krever tabell, felter, heltallsnøkkel og indeks.
Ufullstendig skjema avvises med eksisterende data bevart. Historisk påmelding,
bekreftelse, ventende plan, UnderSending/Uavklart og frister beholdes uten nye
hendelser eller falske administratorstanser. Første faktiske stans etter
oppgradering prøves. Begge eksplisitte SQL-migrasjonshaler er oppdatert.
