# EV05 – eget utvalg for e-postvarsling

## Nødvendig integrasjon med levert UX18 etter publisering

EV05 er publisert i [PR #134](https://github.com/depmartin/Budsjettkalender/pull/134).
Publisert head `7a23c47ad80159d3f01e2951d40c19220f33ce12` og lokal
`2f732c9a19d62548fbe8378d4c13d9fb4949c87c` har samme tree
`d1630e97b35c42fcdb09fca3cdab89ed9861c0a9`. Lokal HEAD er nå avstemt med faktisk
main/MERGE_HEAD `134857de41527e4442ed3f7009620487f13f82f4`, som inneholder levert
UX18/[PR #132](https://github.com/depmartin/Budsjettkalender/pull/132). Ingen umerget
gren er integrert. De to tekstkonfliktene gjelder CI-antall og statusdokumentet;
utviklingsveiledningen er også avstemt. Ingen ny produkt- eller testkode er skrevet.

Alle 35 backendfilene som EV05 eller UX18 endret fra felles EV04-base er bevart med
eksakt samme Git-blob som i sin opprinnelige kandidat. Dette omfatter EV05s utvalg,
delte kontrakter, migrasjoner/snapshot og demooppgradering, sammen med UX18s
MainLayout, kontrast/fokus-CSS, kompatibilitetsprøver og de to CI-kvitteringene.
Ingen pakkelås er endret. EV04-akseptansen, UX18s detaljerte kravkart, overlevering
og daterte historikk er bevart; gjeldende status registrerer levert UX18 og EV05s
egen publiserte kandidat.

Fersk testoppdagelse gir den eksakte unionen av både EV05s **1057/216/330** navn og
UX18s **1024/186/332** navn: **1063 ordinære, 216 SQL Server og 336 nettleser**,
uten manglende navn, ekstra navn eller dubletter. Sammenlikningen skiller store og
små bokstaver, slik at forskjellige teoridata beholdes. De tidligere browservernene
på 330 og 332 avviser det samlede inventaret; det korrigerte vernet krever nøyaktig
336. SQL-vernet krever fortsatt 216. Hoppvern, manglende-TRX-vern, forventninger,
audit, bare-TRX-artefakter og tidsgrenser på 15/20/45 minutter er uendret.

De 33 nettlesertilfellene omfatter alle 16 e-postforløp, de seks nye UX18-tilfellene,
fire rolle-/meny-/mobilforløp i felles layout, seks interne ansvar-/reloadtilfeller
og den berørte relative malregelbyggeren. Dette prøver e-postutvalget, kontrollert
mottaker, tastatur, hopp til innhold, kontrast, forslag/POL/godkjenning og samme frist
i seks flater på den integrerte runtime. Browserprosessen tok 237,532 sekunder;
den ordinære prosessen tok 17,434 sekunder. Dette måler ikke Chromium i CI.

Første restore gjenbrukte NU1900-resultater fra et forsøk uten NuGet-tilgang.
Etter verifisert nettverkstilgang ble alle tre låste restore kjørt med uendret aktiv
audit og isolert HTTP-cache, deretter alle Release-bygg uten advarsler/feil.
Alle 1495 runtimehashene var fortsatt identiske med dem som testene brukte.
De tidligere advarslene og sandbox-forsøket er bevart som historiske logger;
de regnes ikke som et bestått auditbevis.

Ingen ny feil eller bekymring ble observert i de relevante samspillprøvene, så en
ny full lokal nettleserport er ikke kjørt. **Alle 336 Chromium- og 216 ekte SQL
Server-tilfeller samt ordinærporten kreves fortsatt i ny kandidat-CI** etter denne
integrasjonen. SQL Server er kun bygget og oppdaget lokalt; ingen SQL-tilkobling er
konfigurert. Tidligere lokale fullportfeil og visuelle bevis nedenfor er historikk,
og erstattes ikke av de målrettede integrasjonsprøvene.

Integrasjonen følger publisert PR-/CI-oppfølging og har ingen ny full review eller
sikkerhetsaudit. Den utvider ikke den opprinnelige gjennomgangens revisjonsgrunnlag.
Ingen commit, push, produksjonsutsending, utrulling eller ekstern tilgangsendring
er utført av integrasjonsbyggeren. Kontrollert mottaker beviser fortsatt ikke
Entra, Azure SQL, M365 eller ekstern levering.

## Historisk lokal bygging før publisering

Opprinnelig kandidat for [#115](https://github.com/depmartin/Budsjettkalender/issues/115), med
[#110](https://github.com/depmartin/Budsjettkalender/issues/110) som kravkontekst.
Basen er levert EV04, `926ffe74e62999714f6e711327636ecce2070317`, i isolert branch
`codex/115-abonnementsfiltre`. Andre arbeidsflater er bevart. Umerget UX18/PR #132

## Levert atferd

- Påmelding og innstillinger bruker samme `IEpostabonnement`-kontrakt, HTTP-innganger
  og serverhentede kretsidentitet. År/kategorier lagres separat fra kalenderfiltrene.
- Null eller tom liste betyr Alle. Lister normaliseres til sorterte, unike verdier.
  År 1–9999 og definerte kategorier godtas; ugyldige verdier avvises på server.
- Flere år eller kategorier gir union innen dimensjonen, og dimensjonene gir snitt.
  Budsjettår er uavhengig av kalenderdato. Alle omfatter senere nye budsjettår.
- Årsvalg hentes fra serverfiltrert `IFristlesing` med historikk inkludert. Egne
  lagrede år beholdes i skjemaet selv om det ikke lenger finnes synlige frister i året.
- Databaseordnede utvalgsklausuler bevarer ventende treff ved utvidelse og utelukker
  historikk for nytilvalgte områder. Innsnevring og senere gjenutvidelse får fersk
  grense. Samme transaksjon lagrer utvalg, klausuler, versjon og typegrenser.
- Endret matcher hele før- eller hele ettertilstanden. Krysstreff mellom førår og
  etterkategori avvises. Hendelser filtreres før gruppering, førverdi, forklaring og
  plankobling. Dagens godkjente frist og fersk mottakertilgang begrenser alt innhold.
- Begge eksisterende sistekontroller av abonnementsversjon og fristinnhold består.
  Innsnevring under planlegging stanser innhold før adapteren.
- Én nullable JSON-kolonne legges til additivt. Demooppstart oppgraderer EV02/03/04
  atomisk og idempotent. Legacy Ny uten metadata har eksplisitt fallback til dagens
  autoriserte frist; ingen historiske førverdier oppdiktes.

## Kontroller

`EpostabonnementKontrakt` og `DagligEpostKontrakt` deles uendret mellom SQLite og
SQL Server. Nye tilfeller prøver null/tomt, normalisering, validering, varig lesing,
eierskap, stale versjon, samtidige lagringer, Alle/fremtidige år, union/snittutvalg,
utvidelse med bevart ventende innhold, flere utvidelser, innsnevring/gjenutvidelse,
Alle→konkret→Alle, tomt internt snitt, samtidig type-/filterutvidelse, hele før/etter,
krysstreff, relevant gruppering/forklaring og innsnevring ved begge sistekontroller.
Begge commitrekkefølger prøves med like, fremover- og bakoverforskjøvne UTC-ticks.

HTTP prøver alle tre funksjonsroller, ny innlogging, identitetsspoof, ugyldig JSON,
ugyldige år/kategorier, gammel versjon, anonym tilgang og beholdt JSON/CSRF-vern.
Eksisterende tilgangskontrakter for POL, fersk tilgang, avmelding og skjult innhold
beholdes. Ny migrasjonsprøve bevarer alle eksisterende frist-/abonnementsdata og
EV04-hendelser med før/etter/forklaring, status, begge typegrenser, sekvenser, planer
og koblinger. En ventende plan fullføres etter oppgraderingen. Eldre migrasjonsprøvers
bevaringsasserts og faktiske historiske modeller består.

Fire nye ekte Edge/Kestrel-scenarioer (390 og 1280 piksler) prøver tastatur,
påmelding/bekreftelse, serverfiltrerte år, kalenderfiltrenes uavhengighet,
prosessomstart/ny innlogging, administratorpublisering, daglig kjøring, faktisk innhold
hos kontrollert mottaker, Alle/fremtidige år uten tilbakefylling og utflyttingsendring.
Mobilen har ingen horisontal overflyt. Skjermbilder tas på den tokenfrie
innstillingssiden, og kontrolleres visuelt lokalt.

De to første nye nettleserfeilene gjaldt en for bred mottakerlokator som traff to
dagers oppsummeringer. Den nye kontrollen krever én oppsummering med den konkrete
nye fristen og beholder alle innholdsutelatelsene. En ny EV04-fixture måtte også
oppgi den ikke-nullbare Endringssekvens-kolonnen. Ingen produktvern ble svekket.

Den samlede Edge-porten tok 27 minutter og 54 sekunder. Eksisterende
`InternkalenderAtelierTester.Gjoeremaalsregel_bevarer_fem_tidfestinger_alle_runder_ansvar_og_bekreftet_sletting`
med AnkerRelativ feilet i konsollvernet med `ERR_NO_BUFFER_SPACE` ved lasting av
Blazor-rammeverket. Feilen lot seg ikke gjenskape i en isolert etterprøve av alle
fem tidfestingene. Årsaken er ikke fastslått, og fullporten regnes fortsatt som
feilet. Konsollvern, forventninger og tidsgrenser er beholdt.

Visuell kontroll viste deretter at et arvet CSS-kolonneoppsett plasserte
avkrysningsboksen over etiketten. To scoped CSS-filer setter nå uttrykkelig rad og
normal skriftvekt. Dette er de eneste kildeforskjellene etter fullportens start;
`after-full-source-drift.json` dokumenterer dem. De 16 berørte e-postforløpene og
hele den ordinære suiten er kjørt på nytt, og nye mobil-/desktopbilder er inspisert.
Fullportens eldre resultat og isolerte etterprøve er ikke erstattet med en påstått
grønn samlet port. `source-before-browser.json`, `runtime-before-browser.json` og
`source-verified.json` bevarer grunnlaget; siste kandidat bindes i `candidate-files.json`.

Kjør fra repo-roten med det eksakt låste SDK-et:

```powershell

dotnet build backend/Aarshjul.slnx -c Release --no-restore -m:1 -nr:false
dotnet test backend/Aarshjul.slnx -c Release --no-build
dotnet restore backend/Aarshjul.SqlServerTests --locked-mode -m:1 -nr:false
dotnet test backend/Aarshjul.SqlServerTests -c Release --no-restore
dotnet restore backend/Aarshjul.BrowserTests --locked-mode -m:1 -nr:false
dotnet build backend/Aarshjul.BrowserTests -c Release --no-restore -m:1 -nr:false
$env:AARSHJUL_BROWSER_CHANNEL = 'msedge'
dotnet test backend/Aarshjul.BrowserTests -c Release --no-build
```

## Bevisgrenser

Ingen lokal SQL Server-tilkobling er konfigurert. Alle 216 SQL-tilfellene er bygget
og oppdaget; faktisk SQL-kjøring og Chromium kreves fortsatt i kandidat-CI.
Den lokale fullportens ene Edge-feil er heller ikke et bestått samlet bevis.
NuGet-audit og restore kjørte med nettverkstilgang; tidligere sandbox-forsøk med
utilgjengelig NuGet og testhost er ikke godkjent bevis. Ingen audit er slått av.

Kontrollert mottaker beviser ikke Entra, Azure SQL, M365 eller faktisk ekstern
levering. Produksjonsadapterne er fortsatt utilgjengelige. Ingen produksjonsutsending,
utrulling, eksterne tilgangsendringer, commit, push eller PR er utført av byggeren.
