# Atelier UX01 – grunnstruktur og navigasjon

Kandidat for [#76](https://github.com/depmartin/Budsjettkalender/issues/76),
27. oktober 2026. Base: `4776be04919c4466fa1469b225c31ccbd96c55f1`.
[#75](https://github.com/depmartin/Budsjettkalender/issues/75) er den samlede
bestillingen; denne leveransen avgrenser seg til UX01.

## Prøvd atferd

Ordinær åpning på `/` viser Kalender med aktiv hovedinngang. `/kalender` består.
Budsjettår åpner den eksisterende, virksomme Fristlisten på `/budsjettaar`;
`/aarshjul` er fortsatt en direkte inngang til samme visning. Kategorier, budsjettår,
historikk og kretsens filterbevaring er videreført. Månedskalender og tidslinje følger
senere tickets.

Leser, FA-bidragsyter, annen eksisterende bidragsyter og administrator er prøvd mot
ekte Kestrel/Blazor med syntetiske demodata. Bidragsyterne beholder Mine forslag,
Varsler og vanlig Nytt forslag. Administratorens seks områder åpner eksisterende
innhold med lokal navigasjon:

| Område | Virksomme innganger |
| --- | --- |
| Budsjettår og frister | Fristregister, Ny frist, Kø, Last opp, Generér |
| Årsmal | Gjentaksregler og Ny gjentaksregel, med dagens regelredigering |
| Grupper og innsyn | Grupper og Innsyn |
| Eksport og deling | Eksporter, Del kalender og Data |
| Internkalender | Internrunder, Mine gjøremål og Gjøremålsregler |
| Administrator-innstillinger | Beskrevet, fungerende inngang til dataforvaltning |

Administrator-innstillinger står rett under Internkalender. Det er ingen ny fase-
eller rolleforvaltning i kandidaten. Alle eksisterende direkte sider og deres
serverpolicyer består, inklusive ErSbr som egen grense.

Mobilprøven bruker 390 × 844 piksler. Meny kan åpnes med Enter, betjenes med Tab,
lukkes med Escape med fokus tilbake på knappen og lukkes ved navigasjon med fokus
på den nye overskriften. Lenker har synlig tastaturfokus og aktiv markering.
Alle seks administrasjonsområder nås på mobil uten at hele siden blir bredere enn
skjermen. Brede eksisterende tabeller kan rulles inne i innholdet.
Leser- og administratorskallet er også visuelt kontrollert ved 1440 × 1000 piksler.

## Testbevis og gjentaking

Hovedgrensen er eksisterende `Nettleser.Kjor`: faktisk nettleser, Kestrel, Blazor og
disponibel SQLite-database. Nye tester bruker tilgjengelige navn, synlig innhold,
fokus, ARIA-tilstand og faktisk skjermbredde. De leser ikke privat komponenttilstand.

Rød → grønn ble kjørt for tre vertikale atferder:

- `76-01-red.trx` / `76-01-green.trx`: navngitt hovedmeny, Kalender som aktiv start,
  Budsjettår og bidragsyternes innganger.
- `76-02-red.trx` / `76-02-green.trx`: seks virksomme administrasjonsområder med
  lokale innganger og én aktiv område-/underinngang.
- `76-03-red.trx` / `76-03-green.trx`: mobilmeny, tastatur, fokusretur og skjermbredde.

Supplerende HTTP-prøver kontrollerer 401/403/200 for de nye inngangene og de gamle
Kalender-/Årshjul-rutene. Eksisterende avvisnings-, publiserings-, synlighets-,
eksport- og internkalenderprøver beholdes.

SDK 10.0.402, låst restore og Release-bygg. Lokale sluttresultater ligger i
`TestResults/76-final-ordinary.trx` og `TestResults/76-final-browser.trx`.
Alle 629 ordinære tester og 26 nettleserscenarioer passerer med 0 feil og 0 hopp.
CI krever nå 26 nettleserscenarioer, alle uten hopp. Kun TRX lastes opp i CI.
Lokale skjermbilder og disponible databaser blir i nettleserens evidensmappe;
abonnementets tokenlenker avbildes ikke.

Kjør fra repo-roten med SDK-en i `global.json`:

```powershell
dotnet restore backend/Aarshjul.slnx --locked-mode
dotnet restore backend/Aarshjul.BrowserTests --locked-mode
dotnet build backend/Aarshjul.slnx -c Release --no-restore
dotnet build backend/Aarshjul.BrowserTests -c Release --no-restore
dotnet test backend/Aarshjul.slnx -c Release --no-build
$env:AARSHJUL_BROWSER_CHANNEL = 'msedge' # Windows med installert Edge
dotnet test backend/Aarshjul.BrowserTests -c Release --no-build
dotnet run --project backend/Aarshjul.Web --launch-profile demo
```

Åpne `http://localhost:5014/demo` for lokal prøving. Bruk `demo-fag`, `demo-fa`,
`demo-finfag` og `demo-admin`. For målrettet navigasjonsregresjon brukes
`--filter FullyQualifiedName~TilgangTester`. Se [utviklingsoppsettet](../development.md)
for Chromium og alternative SDK-/evidensstier.

## Review og avgrenset retting

Samlet Standards-/Spec-review av
`a9221b5ff9d05b55e9d1fcae1393bf060566a958` fant ingen standardbrudd eller
kravavvik. Standards hadde ett P3-forbedringspunkt: områdene, underinngangene,
aktivt område og internkalenderens policy var koblet sammen via arrayposisjoner.
Forvaltningsnavigasjon samler nå områdenavn, inngang, eksakte stier/stiprefiks,
underinnganger og eventuell policy i ett lokalt objekt per område. Standardområdet
er navngitt, og ErSbr følger internkalenderobjektet uavhengig av rekkefølge.
Lenker, tekst, aktiv markering, rutematching og policyer er beholdt.

En separat sikkerhetsaudit av samme faste commit fant ingen funn.
`TestResults/76-security-http-unsandboxed.trx` viser 74 HTTP-, tilgangs-,
synlighets-, internkalender- og abonnementstilfeller;
`TestResults/76-security-browser-unsandboxed.trx` viser fire reelle Edge-/Kestrel-
scenarioer for tilgang og navigasjon. Alle passerte med 0 feil og 0 hopp.
Auditen gjelder kandidaten før den avgrensede rettingen; målrettet etterkontroll
av selve rettingen utføres separat.

Etter kodeendringen passerte fire HTTP-rolleprøver i
`TestResults/76-reviewfix-http.trx` og alle fire tilgangs-/navigasjonsscenarioer i
`TestResults/76-reviewfix-navbrowser.trx`, inklusive de seks områdene,
underinnganger, direkte innganger og mobil/tastatur. Begge Release-bygg passerte;
bare den eksisterende CS0649-advarselen i Runde.razor ble rapportert.
Hele sluttkjøringen etter siste kodeendring passerte med 629 ordinære tester og
26 nettleserscenarioer, 0 feil og 0 hopp:
`TestResults/76-reviewfix-final-ordinary.trx` og
`TestResults/76-reviewfix-final-browser.trx`.

endret. Eksisterende produksjonsinnlogging og returadresser er beholdt i kode;
