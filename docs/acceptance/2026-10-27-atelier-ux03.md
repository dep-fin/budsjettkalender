Lokal kandidat for [#78](https://github.com/depmartin/Budsjettkalender/issues/78),
27. oktober 2026. Base: `a65ae35c1edd74c2780f347948f7e5962e11f20e`, den mergede
UX02-leveransen i [PR #97](https://github.com/depmartin/Budsjettkalender/pull/97).
Hele [#75](https://github.com/depmartin/Budsjettkalender/issues/75) og kommentarene er kravkontekst.
Den godkjente grønne [Atelier-referansen](https://github.com/depmartin/Budsjettkalender/tree/e517ed91a066872c3947e8c463704655b6cd3313/docs/prototypes/atelier-samlet-2026-10-27)
og de faktiske UX01-/UX02-bildene er brukt ved visuell kontroll.

## Implementert atferd og kontrakt

Kalenderen har eget eksplisitt års-/kategoriutvalg, Velg alle, Fjern alle, søk og
Nullstill filtre. Ved første åpning velges alle tilgjengelige autoriserte budsjettår.
Nullstilling velger disse årene eksplisitt, slår på Budsjett og Gul bok, slår av
Regnskap og tømmer søket. Valgt periode beholdes. Tomt års- eller kategoriutvalg gir
null treff. Kalenderen sender aldri en tom samling til leseporten som uttrykk for
dette nullutvalget. Andre konsumenters null/tom=alle-kontrakt er uendret.

År danner eksakt union; kategori og hel kalenderperiode danner snitt i den
eksisterende serverautoriserte IFristlesing-spørringen. Søk avgrenser på serveren
i dette allerede autoriserte periodeutvalgets tittel/notat, uten hensyn til store/små
bokstaver og med innledende/avsluttende mellomrom trimmet. Søk endrer ikke årslisten.
Årsvalgene hentes separat fra hele det autoriserte, godkjente utvalget med historikk,
uavhengig av måned, søk, valgte år eller kategori. Ingen egen lesedatabase eller
endret HTTP-kontrakt er innført.

Kalendertilstand er scoped i Blazor-kretsen og samler valgt dato, år, kategori og søk
for videre kalenderpresentasjoner. Agenda/detaljer og intern navigasjon tilbake
beholder tilstanden. Den er atskilt fra Fristlistens tidligere filter/historikk og
lagres ikke varig som personlig preferanse. Periodetekst, aktive filtre, telling,
minimarkører, månedsfelt, dagsagenda og detaljer bygger på samme aktive utvalg.

## Faktiske prøver

Tre nye Playwright-scenarioer bruker ekte Edge/Kestrel/Blazor, egne disponible
SQLite-databaser og UI-opprettede syntetiske frister. Fire nye kontrakttilfeller
bruker eksisterende IFristlesing-grense. Ingen tester binder filterkravene til
privat komponenttilstand eller CSS.

| Krav | Bevis |
| --- | --- |
| Eksakt union | 2026 + 2028 viser begge løp, utelater 2027, gir to treff og to frister i minidagens tilgjengelige navn; ett/alle/ingen år prøves |
| Snitt og søk | Tittel og notat matcher blandet bokstavstørrelse og norske tegn; kategori begrenser videre; neste måneds treff kommer ikke med; null kategorier og ukjent søk gir null |
| Nullstilling | Tømmer søk, velger alle autoriserte år, Budsjett/Gul bok på og Regnskap av; Regnskap kan deretter velges eksplisitt |
| Årsvalg og sikkerhet | Leser får historisk regnskapsår også når kategori er av og måneden er en annen; skjulte POL-/FIN-FAG-år og upublisert forslagsår finnes ikke som valg; søk/telling/markører og full DOM røper ikke skjult tittel eller ID |
| Kontekst | År/kategori/søk og november 2030 beholdes gjennom agenda → detaljer → Escape → agenda → kalender; mobilnavigasjon til Fristliste/tilbake beholder egen kalenderperiode og tomt utvalg |
| Mobil | Reell 390 × 844: alle filterhandlinger, historisk frist, minikalender, månedsagenda og hovedmeny brukes; sidebredde er 390 |
| Leseport | Eksakt årsunion i snitt med kategori, periode og synlighet; full historisk autorisert årsliste; null og tomme samlinger betyr fortsatt alle for øvrige konsumenter |

UX02s dato-/ISO-/DateOnly-grenser, kildevern, tentative måneder, reelle rollehandlinger,
avbrutt dialogimport, ventemerke, kø, forslag, eksport, abonnement og internkalender
beholdes i hele regresjonssuiten. Den tidligere enkeltårsprøven velger nå først
Fjern alle fordi kalenderens startutvalg er eksplisitt alle. Fristlisteprøven velger
sin kategori selv, slik at separat historikk og filterkontrakt fortsatt prøves.

## Rød → grønn og sluttkjøring

`TestResults/78-years-red.trx` feilet gjennom ekte UI ved manglende Fjern alle-knapp.
Etter implementering passerte den samme prøven i `78-years-green.trx`.
`TestResults/78-search-red.trx` feilet ved manglende søkefelt; den samme søke-/
nullstillingsflyten passerer i sluttkjøringen. Mellomkjøringer fant også to
testsynkroniseringsbehov: vent på dialogens synlige fokusretur før Escape, og bruk synlig
periodeoverskrift på mobil der rutenettet har et agendaalternativ. Mobilnavigasjon
åpner hovedmenyen før lenken velges. Ingen vilkårlige søvnventinger er lagt i testene.
Den første hele nettleserkjøringen i `78-pre-focus-browser.trx` hadde 35/36 bestått:
detaljinnholdet kunne være rendret før dialogens JavaScript hadde satt riktig
Escape-/fokustilstand. Testen venter nå på den observerbare fokusreturen før hvert
Escape. Den målrettede prøven passerer i `78-search-focus-green.trx`.

Etter siste kode- og testendring passerer **633 ordinære tester og 36 reelle
Edge/Kestrel-scenarioer, 0 feil og 0 hopp**, med SDK 10.0.402.
Sluttbevis: `TestResults/78-final-ordinary.trx` og `TestResults/78-final-browser.trx`.
Låst restore og Release-bygg av løsning, nettleserprosjekt og SQL Server-prosjekt
passerer uten deaktivert audit. Den eksisterende CS0649-advarselen i Runde.razor
er uendret. CI krever nøyaktig 36 nettleserscenarioer og beholder ekte SQL Server
og Chromium som obligatoriske porter.

## CI-retting av testsynkronisering

[Første CI-kjøring for PR #98](https://github.com/depmartin/Budsjettkalender/actions/runs/40529195397)
hadde 34 av 36 nettleserscenarioer bestått. Søke-/kategoriprøven og prøven av
autoriserte minimarkører valgte år rett etter Fjern alle, før Blazor hadde rendret
det tomme årsutvalget. Playwright kunne da se det gamle avkryssede feltet og la
CheckAsync fullføre uten en endringshendelse. Den særskilte diagnosen gjenskapte
denne rekkefølgen tre ganger gjennom ekte Kestrel/Blazor med styrt WebSocket-trafikk;
ingen produksjonsfeil ble påvist i de to tilfellene.

Begge scenarioene venter nå på null avkryssede år før nye årsvalg. Deretter venter
de på nøyaktig ønsket årstekst i den tilgjengelige regionen Aktivt kalenderutvalg
før neste kategoriendring. Dette bruker observerbar DOM/status, uten fast venting,
økte tidsgrenser, produksjonsendringer eller endret scenarioantall.

De to rettede scenarioene passerer fem gjentakinger hver, **10 av 10**, med SDK
10.0.402 og ekte Edge/Kestrel/SQLite. Bevis: `TestResults/78-ci-sync-target-1.trx`
til `78-ci-sync-target-5.trx`. Etter siste testendring passerer alle 633 ordinære
tester og alle 36 nettleserscenarioer, 0 feil og 0 hopp. Sluttbevis:
`TestResults/78-ci-sync-final-ordinary.trx` og `TestResults/78-ci-sync-final-browser.trx`.
Disponibel app-/databaseevidens ligger i `TestResults/78-ci-sync-browser/`.
Låst restore og Release-bygg av løsning, nettleserprosjekt og SQL Server-prosjekt
passerer med audit på; bare den tidligere CS0649-advarselen i Runde.razor gjenstår.
Oppdatert Chromium-/SQL Server-bevis krever ny CI-kjøring på publisert kandidat.

## Visuell kontroll

16 faktiske fullsidebilder er tatt og inspisert fra egen Kestrel/Edge-instans i
`TestResults/78-visual/`, for leser og administrator på 1440 × 1000 og 390 × 844.
Hver rolle/bredde har årsunion 2026+2028, søk med kategorisnitt, tomt årsutvalg og
tomt kategoriutvalg. `capture-result.json` har tom feilliste og sidebredde lik
visningsbredden i alle tilfellene. Alle bilder viser telling og aktiv kontekst.

Grønn Atelier-palett, fire ruter i merket, Segoe UI, header/sidebar, luft og
minikalender er bevart mot UX01/UX02. Søk, årsavkryssing, tomtekst og mobilagenda
er lesbare uten klipping. Syntetisk POL-år finnes kun i administrators årsvalg.
Ingen abonnementsside eller bearer-URL inngår i bildene. Script, bilder, database
og applogg er ignorert lokal evidens og lastes ikke opp i CI.

## Gjentaking og bevisgrenser

Bruk SDK i global.json og [utviklingsoppsettet](../development.md).

```powershell
dotnet restore backend/Aarshjul.slnx --locked-mode
dotnet restore backend/Aarshjul.BrowserTests/Aarshjul.BrowserTests.csproj --locked-mode
dotnet build backend/Aarshjul.slnx -c Release --no-restore -m:1 -nr:false
dotnet build backend/Aarshjul.BrowserTests -c Release --no-restore -m:1 -nr:false
dotnet test backend/Aarshjul.Tests -c Release --no-build --filter FullyQualifiedName~KalenderutvalgTester
dotnet test backend/Aarshjul.BrowserTests -c Release --no-build --filter FullyQualifiedName~KalenderfilterTester
dotnet test backend/Aarshjul.slnx -c Release --no-build --logger 'trx;LogFileName=78-final-ordinary.trx' --results-directory TestResults
dotnet test backend/Aarshjul.BrowserTests -c Release --no-build --logger 'trx;LogFileName=78-final-browser.trx' --results-directory TestResults
```

På Windows ble AARSHJUL_DOTNET satt til den fulle SDK-banen og
AARSHJUL_BROWSER_CHANNEL=msedge. Lokal SQLite/Edge dokumenterer ikke faktisk
SQL Server/Chromium, Azure SQL, Entra eller M365. SQL Server-prosjektet er bygget,
men ikke kjørt lokalt; de ekte CI-jobbene må passere på publisert kandidat.
Uavhengig Standards-/Spec-review, separat sikkerhetsaudit, PR og merge gjenstår
ved denne byggeroverleveringen. Ingen deploy er utført. Uke-/listevisning og
arbeid etter #78 inngår ikke i endringen.
