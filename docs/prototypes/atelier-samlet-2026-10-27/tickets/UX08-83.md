# UX08: Atelier: lagret felles fasemal under Administrator-innstillinger

Blocked by: #82

Hovedoppgave: #75
Plan-ID: UX08. Avgrenset leveranse, men ikke startklar før Blocked by er lukket.
Dekker historier i #75: 62, 63, 64, 65, 66, 70, 72, 84.

## Problem Statement

Prosessfasene må vedlikeholdes av administrator og være like for alle år og lesere, også etter omstart.

## Solution

Lever varig felles fasemal med administratorbeskyttet redigering under Administrator-innstillinger → Faseinndeling.

### Akseptansekriterier

- [ ] De fem standardfasene er identiske med #75 og kan leses av alle autoriserte lesere.
- [ ] Admin kan lagre navn/grenser; endringen brukes i flere budsjettår og leservisningen.
- [ ] Mal og versjon bevares etter ny sesjon og omstart; utdatert fane avvises forståelig.
- [ ] Tomme navn, ikke-stigende grenser og ugyldig sluttgrense avvises uten lagret mutasjon.
- [ ] Leser og uautorisert serverkall kan ikke oppdatere malen.
- [ ] Alle fristidentiteter, datoer, innhold, presisjon, status, kilde og synlighet er uendret etter faseendring.
- [ ] Frister utenfor fasevinduet er fortsatt synlige.

## User Stories

1. Som administrator vil jeg endre navn og månedsgrenser, slik at fasene ikke krever kodeendring.
2. Som administrator vil jeg bruke én mal for alle år, slik at årsspesifikke avvik unngås.
3. Som bruker vil jeg se samme faser etter ny sesjon og omstart, slik at malen er felles.
4. Som administrator vil jeg få avvist ugyldige grenser og gammel versjon, slik at malen ikke blir selvmotsigende eller overskrives.
5. Som leser vil jeg se endringene uten skrivehandlinger, slik at prosessen er forståelig.
6. Som administrator vil jeg bevare alle fristdata ved faseendring, slik at presentasjon ikke flytter frister.

## Implementation Decisions

- Standardfasene er oktober t−2–februar t−1; mars–september t−1; oktober–desember t−1; januar–desember t; januar–april t+1, med avklarte navn.
- Grenser er relative måneder, skifte den første, og siste måned inkludert. Ingen unntak per budsjettår.
- Bruk én tydelig lagrings-/oppdateringsgrense med versjonskontroll. Dokumenter minste nødvendige skjema/migrasjon og seed av standardmal.
- Forvaltning flyttes fra Årsmal til Administrator-innstillinger. Kontekstuelle snarveier åpner samme forvaltning.

## Testing Decisions

- Viderefører avklart testgrense fra #75: eksisterende reelle nettlesertester mot Kestrel/Blazor er hovedgrensen, med dagens tjenestekontrakter for roller, synlighet og publisering. Test ekstern atferd og lagret resultat, ikke privat tilstand eller CSS.
- Reell UI og samme avgrensede lagringsport: lagre, les på nytt/etter omstart, prøv leser og gammel versjon.
- Bevis uendrede fristdata før/etter, samt oppgradering på reell SQL Server dersom ny migrasjon innføres.
- Før ferdigstilling: relevante regresjoner, Standards-/Spec-review, nødvendig sikkerhetsaudit og grønne ordinære/SQL Server-/nettleserjobber etter prosjektets regler. Lokal demo erstatter ikke Azure/Entra/Outlook-bevis.

## Out of Scope

- Årsspesifikke maler eller fristgenerering fra faser.
- Administratortildeling og endring av gjentaksreglenes eksportformat.
- Automatisk publisering, stille POL-valg, endret synlighet ved endringsforslag eller uautorisert produksjonsutrulling.
