# UX16: Atelier: internkalender med runder, egne gjøremål og gjøremålsregler

Blocked by: #90

Hovedoppgave: #75
Plan-ID: UX16. Avgrenset leveranse, men ikke startklar før Blocked by er lukket.
Dekker historier i #75: 27, 28, 29, 74.

## Problem Statement

SBRs interne arbeidsflater må passe inn i Atelier og fortsatt være skilt fra publiserte frister.

## Solution

Moderniser Internkalender med dagens runder, gjøremål, egne oppgaver og regel-/synkroniseringsflyt.

### Akseptansekriterier

- [ ] Runder kan opprettes/åpnes/slettes og gjøremål opprettes/redigeres/fullføres/gjenåpnes med dagens ansvar og hvem/når.
- [ ] Mine gjøremål fungerer på tvers av runder og ansvarligfilter virker.
- [ ] Alle eksisterende tidfestingstyper og venter på ankerdato bevares.
- [ ] Gjøremålsregler kan vedlikeholdes, og synkronisering viser tillegg/endring/fjerning etter eksisterende regler.
- [ ] Avhukede og manuelt endrede gjøremål endres ikke stille ved synkronisering.
- [ ] Leser/bidragsyter avvises på server, og ingen interne oppgaver dukker opp som publiserte frister.

## User Stories

1. Som SBR-bruker vil jeg finne runder og egne gjøremål, slik at det interne arbeidet er samlet.
2. Som SBR-bruker vil jeg registrere raskt eller med fullt skjema, slik at ulike oppgaver kan håndteres.
3. Som SBR-bruker vil jeg vedlikeholde ansvarlige og se fullføringens hvem/når, slik at oppfølgingen er tydelig.
4. Som SBR-bruker vil jeg se venter på ankerdato fremfor gjettet dato, slik at uavklart tidfesting er ærlig.
5. Som SBR-bruker vil jeg kontrollere synkroniseringsforslag uten å miste utført/manuelt arbeid, slik at reglene kan videreføres.
6. Som annen bruker vil jeg ikke motta interne gjøremål, slik at det interne skillet består.

## Implementation Decisions

- Gjenbruk IInternkalender og IGjoeremaalRegler med dagens ErSbr-policy.
- Runder og interne gjøremål er egne enheter, ikke kalenderens publiserte frister.
- Bevar alle eksisterende tidfestingstyper og ansvarlige, ikke bare den forenklede HTML-demoens felt.
- Synkronisering bevarer eksisterende vern for avhukede/manuelt endrede gjøremål og presenterer forslag før vedtatt endring.

## Testing Decisions

- Viderefører avklart testgrense fra #75: eksisterende reelle nettlesertester mot Kestrel/Blazor er hovedgrensen, med dagens tjenestekontrakter for roller, synlighet og publisering. Test ekstern atferd og lagret resultat, ikke privat tilstand eller CSS.
- Eksisterende InternkalenderTester og kontrakter for runder, tidfesting, ansvar/fullføring og synkronisering.
- Reell UI med tastatur og mobil; ingen prototypeklikk erstatter tjeneste-/serverbevis.
- Før ferdigstilling: relevante regresjoner, Standards-/Spec-review, nødvendig sikkerhetsaudit og grønne ordinære/SQL Server-/nettleserjobber etter prosjektets regler. Lokal demo erstatter ikke Azure/Entra/Outlook-bevis.

## Out of Scope

- Nye arbeidsflytregler eller endring av SBR-policy.
- Sammenslåing av interne gjøremål og publiserte frister.
- Automatisk publisering, stille POL-valg, endret synlighet ved endringsforslag eller uautorisert produksjonsutrulling.
