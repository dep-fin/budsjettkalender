# UX14: Atelier: grupper og innsyn med bevarte tilgangsregler

Blocked by: #88

Hovedoppgave: #75
Plan-ID: UX14. Avgrenset leveranse, men ikke startklar før Blocked by er lukket.
Dekker historier i #75: 28, 29, 47, 48, 71.

## Problem Statement

Gruppeforvaltning og innsynskontroll må få samme formspråk uten å miste tilgangsmodell eller eksisterende funksjoner.

## Solution

Moderniser Grupper og innsyn med dagens gruppe-CRUD og autorisert gruppelesing.

### Akseptansekriterier

- [ ] Opprett/navneendre/aktiver/deaktiver fungerer med dagens validering og stabile referanser.
- [ ] Gruppens publiserte frister og detaljer/kilder stemmer med autorisert leseport.
- [ ] Gruppeinnsyn har ingen skrivekontroller, ventemerke eller lekkende forslag/tellinger.
- [ ] POL velges fortsatt aktivt og Entra-/manuelle medlemskap endres ikke av UI-omlegging.
- [ ] Uautoriserte serverhandlinger avvises; mobil/tastatur og feltfeil fungerer.

## User Stories

1. Som administrator vil jeg vedlikeholde navn/aktivitet med stabil gruppekode, slik at referanser ikke brytes.
2. Som administrator vil jeg se som en gruppe, slik at publisert innsyn kan kontrolleres.
3. Som gruppeleser vil jeg slippe administrative merker og forslagmetadata, slik at skjult arbeid ikke avsløres.
4. Som administrator vil jeg beholde eksplisitt POL-valg, slik at politisk synlighet ikke tildeles automatisk.
5. Som bruker vil jeg betjene skjema og feil med tastatur/mobil, slik at funksjonen er tilgjengelig.

## Implementation Decisions

- Gjenbruk IGruppetjeneste og dagens synlighetskontekst; #44s implementering og senere rettinger er eksisterende grunnlag.
- Deaktivering fjerner nye valg og bevarer tidligere referanser; kode endres ikke og grupper slettes ikke via ny UI.
- Gruppelesing filtreres på server og skjuler VenterEndring og annen administrativ metadata.
- Manuell medlemskapsadministrasjon eies av #45, ikke denne visuelle leveransen.

## Testing Decisions

- Viderefører avklart testgrense fra #75: eksisterende reelle nettlesertester mot Kestrel/Blazor er hovedgrensen, med dagens tjenestekontrakter for roller, synlighet og publisering. Test ekstern atferd og lagret resultat, ikke privat tilstand eller CSS.
- Utvid eksisterende GruppeadministrasjonTester, TilgangTester og synlighets-/gruppekontrakter.
- Test faktisk synlig innhold og lagret gruppe, ikke CSS alene.
- Før ferdigstilling: relevante regresjoner, Standards-/Spec-review, nødvendig sikkerhetsaudit og grønne ordinære/SQL Server-/nettleserjobber etter prosjektets regler. Lokal demo erstatter ikke Azure/Entra/Outlook-bevis.

## Out of Scope

- Medlemskapsoverstyring i #45 og ny administratortildeling.
- Endring av hvilken gruppe som gir hvilket innsyn.
- Automatisk publisering, stille POL-valg, endret synlighet ved endringsforslag eller uautorisert produksjonsutrulling.
