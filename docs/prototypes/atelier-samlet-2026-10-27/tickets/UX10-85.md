# UX10: Atelier: regelliste med kategorifilter, milepælmerke og kronologisk sortering

Blocked by: #84

Hovedoppgave: #75
Plan-ID: UX10. Avgrenset leveranse, men ikke startklar før Blocked by er lukket.
Dekker historier i #75: 77, 78, 79, 87, 88, 89.

## Problem Statement

Administrator trenger oversikt over hvilke regler som finnes og rekkefølgen i budsjettløpet.

## Solution

Lever egen Eksisterende gjentaksregler med kombinasjonsfilter, avledet sammenheng og kronologisk sortering for valgt beregningsår.

### Akseptansekriterier

- [ ] Liste og registreringsflate er separate og hver eksisterende regel kan åpnes for redigering.
- [ ] Søk + flere kategorier + sammenheng gir korrekt snitt; tom kategori gir null og tydelig tomtilstand.
- [ ] Lite symbol/tekst markerer bare selvstendige milepæler, og avhengig mellomledd forblir Avhengig.
- [ ] Standard er tidligst først; senest først og norsk tittelrekkefølge virker.
- [ ] Valgt målår viser korrekte kalenderdatoer før/i/etter budsjettåret og kan endres uten datalagring.
- [ ] Tentative måneder, like datoer og uberegnbare regler har stabil og forklart rekkefølge.
- [ ] Filtre/sortering beholdes ved redigering, visningsretur og kombinasjon; kildereglene er uendret.
- [ ] Mobil/tastatur gir tilgang til alle rader, filtre og feilforklaringer.

## User Stories

1. Som administrator vil jeg filtrere på flere kategorier og søke, slik at aktuelle regler blir enkle å finne.
2. Som administrator vil jeg skille selvstendige milepæler, andre selvstendige og avhengige, slik at utgangspunktene er tydelige.
3. Som administrator vil jeg beholde avhengig-merket på et mellomledd, slik at det ikke forveksles med selvstendig milepæl.
4. Som administrator vil jeg sortere etter beregnet dato for valgt budsjettår, slik at hele prosessen over flere kalenderår er lesbar.
5. Som administrator vil jeg velge senest først eller tittel, slik at jeg kan undersøke listen på ulike måter.
6. Som administrator vil jeg se uberegnbare regler sist med forklaring, slik at feil ikke skjuler regler.
7. Som administrator vil jeg gå til redigering og tilbake med filtre/sortering beholdt, slik at oversikten ikke må settes opp på nytt.

## Implementation Decisions

- Milepæl er kun visuelt avledet: ikke-relativ regel med avhengige. Relativ regel er alltid Avhengig. Ikke innfør lagret milepæl-boolean eller ny regeltype.
- Sorteringen bruker eksisterende beregning for eksplisitt målbudsjettår, inkludert årsforskyvning og ankre; ingen sortering bare på måned/dag.
- Tentativ måned plasseres på månedsnivå uten presentert oppdiktet dagsdato. Like datoer sorteres deterministisk på norsk tittel og stabil identitet.
- Uberegnbare regler kommer sist både stigende og synkende; vis årsak. Sortering, filtre og merker muterer ikke regler eller publiserer forslag.

## Testing Decisions

- Viderefører avklart testgrense fra #75: eksisterende reelle nettlesertester mot Kestrel/Blazor er hovedgrensen, med dagens tjenestekontrakter for roller, synlighet og publisering. Test ekstern atferd og lagret resultat, ikke privat tilstand eller CSS.
- Reell UI med minst tre kategorier, selvstendig anker, avhengig kjede, årsforskyvning, tentative datoer og manglende anker.
- Prøv rekkefølge før/etter redigering, flere målår, begge datoretninger, tittel og uendrede lagrede regler; gjenbruk eksisterende beregningsgrenser.
- Før ferdigstilling: relevante regresjoner, Standards-/Spec-review, nødvendig sikkerhetsaudit og grønne ordinære/SQL Server-/nettleserjobber etter prosjektets regler. Lokal demo erstatter ikke Azure/Entra/Outlook-bevis.

## Out of Scope

- Endring av regelenes betydning eller automatisk flytting av godkjente frister.
- Ny lagret milepælstatus eller personlig varig sorteringspreferanse.
- Automatisk publisering, stille POL-valg, endret synlighet ved endringsforslag eller uautorisert produksjonsutrulling.
